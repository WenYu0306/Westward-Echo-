# READ 降档：qwen3.8-max → qwen3.8-flash

> **状态：已采纳（2026-10-26），有条件。** 默认档已改（`src/config.py`
> `DEFAULT_NODE_MODELS["read"]`），护栏是 `scripts/qe_delivery_check.py`。
> 只有 READ 降档；READBACK 与 REVIEW_TERMS 仍为 qwen3.8-max——这两个节点没有测。

## 决策

READ 节点默认模型从 `qwen3.8-max`（12/36 元/M）改为 `qwen3.8-flash`（0.8/2.7 元/M）。
同一 provider，不走智谱——READ 当年从 GLM 移开就是因为 1301 内容过滤会拒付真实网文，
换成 `glm-5.3-flash` 会把那个风险重新引回来，所以本次降档**只在 Qwen 内部换档**。

## 证据

实验对象：《地府叫我小先生》6 章（11 / 173 / 604 / 1238 / 1800 / 2301），
两臂跑同一流水线（READ → REVIEW_TERMS → WRITE），WRITE 臂固定为 glm-5.3-flash。
原始数据：`archive/ab_read_tier_20261026/`。

| 指标 | A（qwen3.8-max） | B（qwen3.8-flash） | 变化 |
|---|---|---|---|
| 6 章成本 | ¥3.3026 | ¥0.7754 | **−76.5%** |
| 每章成本 | ¥0.5504 | ¥0.1292 | −76.5% |
| 6 章墙钟 | 1877.9 s | 1453.8 s | **−22.6%** |
| 每章 p50 | 306.1 s | 228.3 s | −25.4% |
| 每章 p95 | 401.2 s | 292.6 s | −27.1% |
| MetricX-24 均分（36 配对段） | 15.556 | 15.167 | **−0.389** |
| MetricX 95% 自举 CI | — | — | **[−1.175, +0.347]** |
| 段级胜负 | 16 段更优 | 20 段更优 | 0 平 |

MetricX-24 是 WMT'24 官方指标，0–25，**越低越好**，无参考（QE 模式），本地推理。
6 章里 B 的均分全部不高于 A（逐章 Δ：−0.01 / −0.21 / −0.23 / −1.08 / −0.78 / −0.02）。

**盲评不可用。** 双顺序（A 在前 / B 在前各判一次）6 章里 3 章翻转成 noise，
即裁判按位置而不是按质量选。任何基于这组盲评的胜负结论都是伪造的，
所以本次没有采用盲评，只把它记录在 `results.json` 的 `verdicts` 里。

## 这个结论的边界（重要）

- **不能声称"质量相同"。** CI 跨 0 意味着这 6 章既没能证明 flash 更好，也没能证明
  max 更好；上界 +0.347 意味着最坏情况下 flash 可能差约 0.35 分（0–25 量表）。
- **不能外推到别的文体。** 样本只有一本民俗灵异网文。科幻（《间客》）、
  无限流（《无限恐怖》）各有自己的术语密度和长句结构，没有测。
- **成本节省是确定的，时间节省是确定的，质量等价是不确定的。** 决策按
  "已证实省钱 + 未证实质损 + 有可执行的护栏" 做出，而不是按"已证实等价"。

## 护栏：交付前必跑

```bash
python3.11 scripts/qe_delivery_check.py --book difu
python3.11 scripts/qe_delivery_check.py --book limitless_horror
```

对固定抽取的 6 章、每章 6 段做 MetricX 打分（本地、零 API 费用），
与 `archive/qe_baseline/<book>.json` 逐段配对比较。基线取自**降档前**的交付版本。

判定：

| verdict | 含义 | 退出码 / 动作 |
|---|---|---|
| `ok` | 退化 ≤ +0.5 分 | 0，放行 |
| `inconclusive` | 退化 > +0.5 分，但 CI 仍含 0 | 0，记录但不阻断 |
| `worse` | 退化 > +0.5 分，且 CI 排除 0 | 2，回退 |
| `no_overlap` / `insufficient` | 没有任何可比段，或只有 1 个配对段 | 3，护栏失效，需重跑 |
| 分数条数 ≠ 输入段数 | MetricX 输出被截断 | 3，不给结论 |

**只有"确实比较过、且确实更差"才会退 2。** 护栏本身跑不动（输出截断、
章节结构变了、缓存分数陈旧）一律是 3，不会伪装成通过——一个把"没比较"读成
"没问题"的质量闸门比没有闸门更糟。

阈值 `--max-delta`（默认 0.5）是容忍度，不是测量精度。取 0.5 是因为
A/B 的 CI 上界是 +0.347——阈值必须大于"已观测到的最坏情况"，否则护栏
会在实验本身的不确定性里误报。

## 回退

不改代码：

```bash
# .env
XIDU_NODE_MODEL_READ=qwen3.8-max
```

或把 `DEFAULT_NODE_MODELS["read"]` 改回 `QWEN_MODEL`。回退后重跑
`qe_delivery_check.py`，应当回到 `ok`。

## 没有做的事

- **READBACK / REVIEW_TERMS 未降档。** 它们和 READ 一样挂在 qwen3.8-max 上，
  但"读得懂吗"的判断是否需要 max 从未测过。`docs/COST_MODEL.md` 估算全 flash
  只花现状的 10%，那是下一个杠杆，但需要自己的 A/B。
- **并行化未做。** 降档只省 22.6% 的时间；串行是跨章连续性的正确设计，
  要提速必须改"每章看到什么上下文"，那是质量决策，不是性能优化。
- **样本量未扩大。** 追加 3 章约需 ¥2.4，CI 大概率仍跨 0，性价比不高。
  `qe_delivery_check.py` 在真实重编译时会把整本书变成配对样本，比 A/B 更有效。

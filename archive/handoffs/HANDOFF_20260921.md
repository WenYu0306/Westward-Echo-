## 二、端到端过程中抓出的 5 个真 bug（本次全部修掉）

端到端不只是「验证」，它直接暴露了 5 个测试覆盖不到的真缺陷。**这类 bug 是变异测试要防的东西，先记在这里**。

### bug 1：fidelity gate 把 READ 的**解释性译法**当成干净术语缓存了（最严重）

真实的 e2e 输出：

```
FIDELITY GATE ch1: '鬼节' WRITE='Ghost Festival' READ='Ghost Festival (chapter title: 'Ghost Festival')' — using READ
```

READ（GLM）给的是**带括号解释的串**，`is_single_rendering()` 只挡了 `/`、`—`、` - ` 三种形式，**括号和冒号没挡** → gate 用 READ 的解释串覆盖了 WRITE 干净的 `Ghost Festival` → 落库成「全书必须使用」的术语。这个术语会注入后面每一章。

**修法**：新增 `_is_explanatory()`，把 `(` `)` `:` `/` `—` `–` ` - ` 一律视为 gloss，`is_single_rendering()` 和 `is_valid_rendering()`（硬 curation gate）共用它。

**验证**：拿 e2e 真实落盘的 4 个产物回放 `_post_process`：
- 把 WRITE 的原值放回去 → 现在输出 `Ghost Festival`（gate 不再覆盖）✅
- 用被污染的值直接喂进去 → curation gate 丢弃它，且**结果里也不再有它** ✅

### bug 2：curation gate 丢了坏术语，但坏术语仍然从管线流出去

`_post_process` 里 `new_terms = kept` 只改了局部变量，`result["new_terms_found"]` 没同步。于是被 gate 拒掉的术语照样出现在 API 响应、落盘产物、`_translate_split` 的合并结果里——**gate 拦了个寂寞**。

**修法**：curation 之后把 `result["new_terms_found"] = kept` 写回。

### bug 3：`_build_cold_read_context` 的 `<= 1` 把「只有一个板块」的简报整份丢掉

`if len(parts) <= 1: return ""`。而「只有章节旁白」和「只有人物表」各只占 1 个 part → 这两种简报**都会被整份丢弃**。也就是第 2 章以后、术语表还空的时候，冷读器**什么都拿不到**，而代码里明明为这种情况写了 "This is an early chapter."。

**修法**：改成 `if not parts: return ""`。（off-by-one，不是设计）

### bug 4：`translate_chapter(use_flash_writer=True)` 这个参数是死的

`translate_chapter()` 收了 `use_flash_writer`，但**从不往下传**给 `_translate_once` / `_translate_split`。而 `src/api/routes.py` 有 **4 处**在传 `use_flash_writer=flash_mode`（API 的 flash 模式）。

影响：`write.py` 用这个标志决定 token 记账的 tier（`tier="flash" if flash else "pro"`）→ **API 的 flash 模式记账一直是错的**（全记成 pro）。注意：DeepSeek 时代的 flash/pro 双模型已取消（WRITE 现在恒为 glm-5.3-flash），所以这个 bug 今天**只影响统计/成本口径**，不影响产出质量——但它是个真 bug。

**修法**：把 `use_flash_writer` 从 `translate_chapter` 往下传。

### bug 5：`build_epub` 的章节编号两处各算一遍 → 重复文件 + 悬空引用

OPF 的 id 用 `ch.get('chapter_num', i + 1)`（1 起），ZIP 文件名却用 `ch.get("chapter_num", 0)`（0 起）。章节没有 `chapter_num` 时：

```
zipfile 警告: Duplicate name: 'OEBPS/chapter_0.xhtml'   # 每章都叫 chapter_0，文件互相覆盖
content.opf 里却写着 idref="chapter_1" / "chapter_2"    # 指向根本不存在的文件
```

**修法**：章节号只算一次（`chapter_nums`），OPF id、spine、NCX、XHTML 文件名全部共用。

> 可达性说明：API 路径的 `chapter_num` 来自 `# Chapter N:` 头，恒有值，所以这是**潜在**缺陷（dev 脚本 / 直接调 `build_epub` 会踩）。

## 四、scripts/ 里的断头引用：修完了（而且是彻底修）

上一份交接说 6 个脚本 `from src.encoding import detect_and_read` 断头。**实际是 18 个**（交接漏了 12 个：`ab_memo_test`、`ab_test`、`analyze_difu`、`audit_translate`、`backfill_chapters`、`batch_test`、`compile_script_sample`、`generate_report`、`run_novel`、`run_script_pilot`、`test_difu`、`test_multilang`）。

交接建议的修法（`open(path, encoding="utf-8").read()`）**不能用**：`tests/fixtures/` 里的真实语料相当一部分**不是 UTF-8**：

```
《间客》作者：猫腻.txt          gb18030/gbk
《唐朝工科生》作者：鲨鱼禅师.txt  gb18030/gbk
《全职高手》（精校版全本）.txt    gb18030/gbk
```

所以做法是**恢复一个共享实现**，而不是把 18 处都写死 UTF-8：

- 新增 `src/text_io.py`：`decode_bytes(raw, encodings)`（严格解码阶梯，返回 `None` 表示失败）+ `detect_and_read(path)`（BOM 快判 → 阶梯 → 中文占比启发式 → 兜底 replacement 解码）+ `looks_like_chinese()`。
- **顺手消掉重复实现**：`src/api/routes.py` 里内联的两段解码阶梯（上传路径）改为调用 `decode_bytes(...)`。当初删 `src/encoding.py` 的理由就是「和 routes.py 重复」，现在只有一个实现了。
- 18 个脚本改为 `from src.text_io import detect_and_read`。

**已知局限（写在测试里，不假装没有）**：`big5` 放在 `gb18030` 后面 → GB18030 是超集，会把 Big5 字节解成仍「像中文」的乱码并胜出，所以**真实 Big5 文件会被报成 gb18030**。本仓库所有非 UTF-8 语料都是 GBK 族，阶梯是按这个排的；要真支持 Big5 得上统计检测器（chardet 之类）。这条已写成 `test_big5_is_shadowed_by_gb18030` 固化下来。

3. **`measurements` 的两个真缺口**（本次只记录、未改，因为都涉及领域判断）：

   - **「亿+万」混合写法解析不出**：`_parse_chinese_number` 先判 `万` 再判 `亿`，所以「三亿五千万」（=3.5 亿）走 `万` 分支 → 左半段「三亿五千」解析失败 → 整体返回 `None` → 提示退化成通用形式。**不会崩**，只是少一条具体换算。修法是先判 `亿`（或递归时优先处理 `亿`）。已写成 `test_yi_plus_wan_notation_is_not_parsed` 固化，将来修好会红。
